# ✅ A short glossary for this tutorial

## 🔤 Abbreviations and Full Forms

### 🤖 AI, Claude and Integration Terms

| Abbreviation | Full Form                          | Meaning in this Workshop                                                            |
| ------------ | ---------------------------------- | ----------------------------------------------------------------------------------- |
| **AI**       | Artificial Intelligence            | Broad technology behind Claude and other AI assistants                              |
| **GenAI**    | Generative Artificial Intelligence | AI that generates text, documents, code, designs and other content                  |
| **LLM**      | Large Language Model               | The type of language model underlying conversational AI systems                     |
| **MCP**      | Model Context Protocol             | Standard for connecting AI applications to external tools, resources and prompts    |
| **RAG**      | Retrieval-Augmented Generation     | Retrieves relevant source material before generating an answer                      |
| **API**      | Application Programming Interface  | Programmatic interface through which software systems communicate                   |
| **CLI**      | Command-Line Interface             | Text-based interface for running commands; relevant when discussing Claude Code CLI |
| **SDK**      | Software Development Kit           | Tools/libraries developers can use to build applications against a platform         |

**Workshop distinction:** A **Connector** provides authorised service access, a **Skill** provides a reusable procedure, a **Plugin** packages capabilities, and **MCP** is a protocol through which tools/resources can be exposed. Your guide already uses this distinction in Module 3.

### 🔑 Most Important Terms to Remember

For the live session, I would emphasize only these **12**:

> **AI** — Artificial Intelligence
> **LLM** — Large Language Model
> **RAG** — Retrieval-Augmented Generation
> **MCP** — Model Context Protocol
> **API** — Application Programming Interface
> **PDF** — Portable Document Format
> **CSV** — Comma-Separated Values
> **UI** — User Interface
> **UX** — User Experience
> **PRD** — Product Requirements Document
> **WCAG** — Web Content Accessibility Guidelines
> **W3C** — World Wide Web Consortium

I would **not overload the learner guide with abbreviations that never appear in the actual exercises**. For example, SDK, DOM, URI, KPI, ROI and SOP are useful background terms, but if they do not appear elsewhere in your final guide, I would omit them from the main glossary. A glossary should primarily help learners decode the tutorial—not become another lesson to memorize.
